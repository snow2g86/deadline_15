### A-상품 표 (인앱 상품, 소모성)

| 제품 ID | 이름(한국어) | 설명(한국어) | 가격(대한민국) | 지급 골드 |
|---|---|---|---|---|
| `gold_500` | 500 골드 | 게임에서 쓰는 골드 500개 | 1,200원 | 500 |
| `gold_1200` | 1,200 골드 | 게임에서 쓰는 골드 1,200개 | 2,500원 | 1,200 |
| `gold_3000` | 3,000 골드 | 게임에서 쓰는 골드 3,000개 | 6,500원 | 3,000 |
| `gold_6500` | 6,500 골드 | 게임에서 쓰는 골드 6,500개 | 12,000원 | 6,500 |

- 제품 ID 는 `godot/data/iap.json` 의 `google` 값과 **글자 하나까지 같아야** 합니다.
- 이름 번역(콘솔의 '번역 추가'): en `500 Gold` / es `500 de oro` / ja `500ゴールド` / zh-CN `500金币` / zh-TW `500 金幣` (게임 안 `shop.gold_iap_500` 과 같음, 1,200·3,000·6,500 도 같은 규칙).
- 설명 번역 예: en `500 gold for use in the game` / es `500 de oro para usar en el juego` / ja `ゲーム内で使えるゴールド500個` / zh-CN `可在游戏中使用的500金币` / zh-TW `可在遊戲中使用的500金幣`.
- 유형은 반드시 **소모성(일회성 상품, 재구매 가능)** 이고 구매 옵션은 '구매' 한 가지입니다 [확인 필요: 콘솔이 '인앱 상품'을 '일회성 상품'으로 바꿔 부름].
- 상품 설명에 확률형 문구는 넣지 않습니다 (골드 자체는 확률 아이템이 아님).
- 서버 쪽: stage 에서는 라이선스 테스트 결제(`purchaseType=0`)를 받고, prod 는 거절합니다 (`GOOGLE_ALLOW_TEST_PURCHASES`, server/README).

## F. 권장 진행 순서

1. 0번(이름·이메일·URL 게시·연령 결정) → 병렬로 A1 · B1 · B4(가장 오래 걸림) · C1 · E1 시작
2. A3~A5 / B2~B3: 앱 껍데기 만들고 첫 빌드 올리기 (빌드는 저에게 요청)
3. AdMob C2·C3·C7 완료 → 남은 C4(동의 메시지) · C5(app-ads.txt), 스토어 게시 후 C8(스토어 연결)
4. Cloudflare D1~D9 (stage) → 주소를 저에게 알려 주기 → D10 반영
5. A6·A7 / B5·B6: 상품 등록 + 테스터 → 내부 테스트 / TestFlight 에서 실제 결제·광고 시험
6. 데이터 보안·App Privacy·콘텐츠 등급·광고 ID 선언 (A9~A15, B7~B10)
7. prod 배포(D15 결정 후) → 심사 제출
8. PC(STOVE)는 E5(결제 API 정보)가 풀려야 서버·게임 연동을 시작할 수 있어 별도 일정
